# 场景匹配与兜底链规范

用户输入场景后，**第一步就是匹配**。匹配不到不是"随便套一个"，而是走有规则的三级兜底链。本文件是匹配的执行规范，配合 `template-catalog.md`（模板资产）与 `scenarios.md`（模块矩阵）使用。

## 三级匹配链（强制顺序）

```
用户输入场景
   │
   ├─ ① 关键词精确匹配 → 命中 `template-catalog.md` 的模板（或 scenarios.md 的推荐组合）
   │      未命中 ↓
   ├─ ② 场景大类兜底 → 查「缺口场景 → 基底模板映射表」：命中则套类似模板只换内容
   │      再未命中 → 按「场景大类分组」归入最近的一类，用该类模板/色板，微调业务
   │      未命中 ↓
   └─ ③ 默认通用模板 → default 基底（当前候选：个人成长 moss 纸感）
                          + 按「场景类型 × 最优色板表」选色板
```

## ① 关键词精确匹配

每个场景维护一组关键词/同义词。命中任一个即确定场景。关键词见 `template-catalog.md` 各模板的「场景匹配」列，及 `scenarios.md` 场景名。

示例：
| 用户输入 | 命中关键词 | 场景 |
|---|---|---|
| 想做个记账的 / 记录日常花销 / 开支 | 记账、花销、开支 | 记账理财台 |
| 帮孩子认字 / 识字启蒙 | 识字、启蒙、认字 | 识字启蒙台 |
| 我要考研，做个计划 | 考研、备考 | 学习备考台 |
| 想记录每次露营的装备 | 露营、装备 | T4 山野清单 |

**匹配要点**：
- 优先命中**语义最具体**的关键词（"考研" > "学习"）。
- 一个输入可能命中多场景（"学习+记账"）→ 取**目标人群最明确**者；仍不明则走 ② 大类兜底，告知用户选择。
- 命中模板后仍要按用户本次的具体需求做业务层定制（模板只是视觉基准，不是内容答案）。

## ② 场景大类兜底（未命中时）

未精确命中，但能归入某个「大类」时，用该大类的模板骨架 + 换业务色板。大类划分：

| 大类 | 覆盖场景 | 基底模板（必须低耦合） | 色板倾向 |
|---|---|---|---|
| 学习成长类 | 备考/阅读/技能/课程 | **T1 个人成长**（低耦合通用）或 T8 | 纸感、书卷气、低饱和 |
| 生活记录类 | 露营/旅行/宠物/植物/烘焙 | 已有专属模板的直接用专属（T4/T9/T7）；未命中的用 **T1** | 自然、手账 |
| 效率规划类 | 职场/项目管理/目标 | **T1 个人成长**（moss 苔绿，低耦合） | 沉静、克制的深绿+纸 |
| 财务记账类 | 记账/理财/副业收入 | **T2 技术开发**（CONFIG 含 finance）⚠️先修基线；或 **T1** | 纸感暖色、支出红收入绿 |
| 儿童启蒙类 | 识字/育儿/亲子 | **T10 识字启蒙**（清新绿儿童向，低耦合） | 活泼、大字、大按钮 |

**兜底动作（未命中场景改皮规则，强制按序执行）**：

1. **复制低耦合基底**（T1/T2/T8，或大类表指定的基底）为工作副本。
2. **保留骨架**：导航（PC sidebar/移动 tabbar）、存储层、refreshAll 架构、双端导航、通用载体功能（增删改查/搜索筛选/导入导出/备份提醒）——一行不许删。
3. **删除与场景无关的基底模块**（场景正确性，不是打折扣）。
4. **按场景功能清单增补新模块**：优先用 `component-catalog.md` 的通用组件拼装（进度环/打卡矩阵/热力图/趋势图/饼图/积分商城/翻卡），再写场景专属业务字段与交互；不重复造轮子。
5. **换色板**：从「场景类型 × 最优色板表」取。
6. **冒烟测试全绿**。
7. **沉淀闭环（强制）**：产物质量达标（视觉/功能/冒烟全过）后，沉淀为新模板——存 `examples/` + 登记 `template-catalog.md`（含色板/布局/模块清单/耦合度），下次同场景直接命中，不再走兜底。覆盖度随使用次数增长，兜底链是过渡态而非终点。

### 缺口场景 → 基底模板映射表（高频场景套类似模板，只换内容）

**核心原则：基底必须是「低耦合」模板（T1/T2/T8/T10，通用引擎），禁止用「高耦合」专属模板（T3/T4/T5/T6/T7/T9/T11）作跨场景基底。** 高耦合模板的业务规则（装备清单/审批流程/训练引擎等）写死在代码里，套它改别的场景 = 重写业务逻辑，不是"只换内容"。（耦合度见 `template-catalog.md` 每套的「业务耦合度」字段）

遇到下表场景时不落入第 ③ 级默认兜底，改走此明确映射：

| 缺口场景 | 基底模板（低耦合） | 复用它的载体（保留不动） | 按场景替换/补齐的内容 | 改造量 |
|---|---|---|---|---|
| 习惯打卡 | **T1 个人成长**（moss，低耦合） | 习惯矩阵 + streak + 今日四档区 + 双端导航 | 色板自选；示例数据换通用习惯 | 最小 |
| 记账理财 | **T2 技术开发**（CONFIG 引擎含 finance 模块，低耦合）⚠️需先修基线；或 **T1** | CONFIG 五类模块引擎 + 收支录入 + drawer 导航 | 色板换纸感暖色；模块数据换收支分类；**补场景功能：CSV 导出（BOM 防乱码）、预算进度条** | 小 |
| 阅读管理 | **T1 个人成长**（低耦合） | 通用列表/进度环/日记载体 + 双端导航 | 书单/摘录/阅读进度；**补场景功能：在读/读完分组** | 小 |
| 求职进度 | **T1** 或 **T2**（低耦合） | 通用看板/列表/状态管理载体 | 字段换公司/岗位/阶段/日期；**补场景功能：面试自动置顶提醒、阶段漏斗** | 小-中 |
| 自媒体创作 | **T8 新闻资讯**（低耦合）⚠️需先补底部 tabbar；或 **T1** | 内容卡片流/收藏载体 + 顶栏 | 选题看板（灵感→写作中→已发布）；素材库；**补场景功能：三列看板、平台数据趋势** | 中 |

**映射执行规则**：
1. **载体层保留**：布局骨架（sidebar/tabbar/hero）、存储层、refreshAll 架构、增删改查/搜索筛选排序/状态管理/导入导出等**通用载体功能原样保留**——这些是"工作台骨架能力"，砍了才叫打折扣。
2. **场景层替换**：色板从「场景类型 × 最优色板表」取；业务字段与示例数据现场生成（必须该场景真实感数据）。
3. **场景功能补齐**：从该场景的功能清单（对照 `8-1新增` 提示词 / scenarios.md 推导）补**场景专属功能**——记账=CSV 导出+预算进度条、求职=面试置顶+阶段漏斗、自媒体=三列选题看板。缺一个就是打折扣。
4. **无关功能删掉**：基底模板里不属于该场景的功能（如 T1 的专注计时搬到记账台）应删除——这是场景正确性，不是打折扣。
5. **验收口径**：交付时对照「通用载体功能清单（不能少）+ 场景专属功能清单（不能缺）」，逐项核对后再交。
6. **两坑**：套 T8 需先补底部导航（它无 tabbar）；套 T2 需先修基线（`min-width:1000px` + 外链残留）。
7. 模板可用类似替代：首选映射表基底；若基底缺失或不合规，换另一个低耦合模板（T1 为通用后备）。

## ③ 默认通用模板（仍未命中）

- 基底：**T1 远行（moss 纸感）**——布局最中性、色板最克制、符合通用定位。
- 执行同 ② 级「未命中场景改皮规则」（复制基底 → 保留骨架 → 删无关模块 → 组件库增补场景模块 → 换色板 → 冒烟 → **沉淀为新模板**）。
- 色板：按下表选（这是"最优配色方案"的规则化，不靠现场碰运气）。

## 匹配失败时对用户的做法

1. 告知"未命中专属场景模板，按 [xx 类] 通用方案搭建"。
2. 给出采用的**布局 + 色板**，并允许用户一句话换色板（"换个暖色/深色/鲜艳的"）。
3. 生成的骨架、交互、冒烟流程与命中场景完全一致（匹配只影响视觉基准，不影响工程质量）。
