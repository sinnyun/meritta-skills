# 工作台分层模板库

单文件 HTML 工作台的「分层模板」体系：把"每次都要重写的"沉淀成资产，把"每次都不一样的"留给现场创作。目标质量基线对标 WorkBuddy 内置的 workspace-builder 专家（小台），场景覆盖更广。

## 分层模型（生成任何工作台前先按此分层思考）

| 层 | 固定程度 | 来源 | 说明 |
|---|---|---|---|
| 1 设计系统 | 100% 固定 | `assets/base-shell.html` 内 `:root` 变量 | 配色/圆角/阴影/间距/字体，不许改结构只许换主题色值 |
| 2 工程骨架 | 100% 固定 | `assets/base-shell.html` | 顶栏、今日要处理区、模块槽、存储层（Store）、refreshAll() 刷新架构、导出导入 |
| 3 组件片段 | 半固定按需拼装 | `assets/components/*.html` | 每个组件自包含（HTML+CSS+JS），按场景挑选 3-4 个 |
| 4 业务内容 | 100% 现场生成 | 模型的创作能力 | 字段、文案、具体业务逻辑、模块联动 |

## 工作流（6 步）

0. **匹配场景（新增，第 0 步）**：查 `references/scenario-matching.md` 走三级匹配链——① 关键词精确命中模板/场景 → ② 场景大类兜底 → ③ 默认通用模板 + 按「场景类型 × 最优色板表」选色板。命中模板时，`references/template-catalog.md` 登记了该模板的布局形态/色板/hero/氛围元素作为**审美基准**；未命中时按兜底链走通用基底。匹配结果须在交付说明中告知用户。**命中专属模板 → 直接复制该模板文件为工作副本**（第 0.5 步），在此副本上按提示词"改皮"（品牌/种子数据/hero 文案/色板按需覆盖），**布局、模块、JS 引擎逻辑、双端导航、配色基准一律原样保留**；严禁从零重写模板结构——复制+改皮是命中场景的唯一路径，效果必须等于模板本身。**布局对齐是硬要求**：命中模板的布局形态（如 T1/T2 的左侧 sidebar 导航、T4 的底部 tabbar）必须在 PC 端保留——桌面优先响应式下，PC 端不得丢弃模板的侧栏/导航骨架而退化成纯顶栏；sidebar 导航的模块项对应主区各模块（锚点滚动或页面切换均可），移动端再降级隐藏。**基底选择铁律**：跨场景套模板时必须选**低耦合模板**（T1/T2/T8/T10，通用引擎）作基底，禁止用高耦合专属模板（T3/T4/T5/T6/T7/T9/T11）作跨场景基底——高耦合模板的业务规则写死在代码里，套它改别的场景=重写业务逻辑，不是"只换内容"（各模板耦合度见 `template-catalog.md`）。**功能以场景为准**：功能不打折扣 ≠ 照搬基底全部功能，而是——通用载体功能（增删改查/搜索筛选排序/状态管理/导入导出/双端导航/数据统计）一个不能少；该场景专属功能（对照场景功能清单推导）必须补齐；基底模板里与场景无关的功能应删除（场景正确性，不是打折扣）。
1. **定场景选模块**：查 `references/scenarios.md` 确定场景和模块组合；用户场景不在表内时按"目标人群 + 核心动作 + 激励闭环"自行推导。**模块数量以场景功能清单为准**：命中专属模板或映射基底时，模块数量对齐场景应有的功能（可超 4 个，如记账的支出/收入/预算/账户/账单/借贷/订阅/投资/资产/凭证）；仅未命中任何模板的兜底场景才受"上限 4 个模块"约束。
2. **搭骨架（双路径）**：命中专属模板时——直接用第 0.5 步复制出的模板副本作为骨架，改皮即可（品牌/种子数据/hero 文案/按需换色），模板的布局/模块/JS 引擎/双端导航原样保留，一行不许删；未命中任何模板的兜底场景——按 `references/scenario-matching.md` ②③ 级「未命中场景改皮规则」复制低耦合基底（T1/T2/T8）为工作副本，保留骨架（导航/存储/双端/载体功能），删无关模块、按场景功能清单用组件库增补模块、换色板，冒烟后**沉淀为新模板**；`assets/base-shell.html` 仅在没有合适低耦合基底时作为最后手段。
3. **装组件**：查 `references/component-catalog.md` 选 3-4 个组件，从组件文件的两个标记行之间复制整段（`<style>`+`<section>`+`<script>`）粘进骨架的模块槽；组件需要的 CSS 变量骨架已全部提供。
4. **填内容**：编写第 4 层业务逻辑——各模块的 state 字段、渲染函数、事件处理；渲染函数间严禁互调，一切联动走 `refreshAll()`；预置 3-5 条示例数据（含 1 条逾期），提供「清空示例」按钮。
5. **冒烟自检**：逐条过 `references/quality-checklist.md`，有一条不过就修，修完再交付。
6. **机器验证（强制，不许跳过）**：运行 `node scripts/smoke-test.js <生成的html路径>`——静态层（内联脚本语法、外链扫描、禁用 API 扫描）任何环境必跑且必须全绿；装有 playwright 时自动升级为真机冒烟（双视口零报错、无横向溢出、结构完整、自动截图）。有任何失败项就修复重跑，直到退出码为 0 才允许交付。

## 铁律（压缩自 48+ 案例规范，逐条不可协商）

1. 单文件 HTML，全部 CSS/JS/图标内联；严禁引用任何外部框架、CDN、字体、图标库、图表库。
2. 图表一律内联 SVG 手写；图标一律内联 SVG path，严禁 emoji 当图标。
3. 桌面优先响应式：页面容器 ≤1100px，桌面双列网格（今日区主列 + 模块副列），≤860px 自动降级单列；任何端底线：按钮点击区 ≥44px（儿童向 ≥50px）、输入框字号 ≥16px、底部留 `env(safe-area-inset-bottom)`、表格窄屏改卡片或允许横滚、任何视口无横向溢出。**双端导航铁律（不可丢）**：PC 端必须保留左侧 sidebar 导航菜单（命中模板的布局母版时按母版来），移动端必须保留底部 Tab 导航栏（footer/tabbar，≥44px 高、适配安全区）——PC 端不得丢 menu，移动端不得丢 footer，任一端的模块导航都必须可到达。
4. 首屏顶部必须是「今日要处理」区：逾期标红、昨天未完成自动顺延显示"顺延"角标、每条给一键完成按钮。
5. 首次打开必须有 3-5 条示例数据（含 1 条逾期），严禁空白首屏；提供清空示例按钮。
6. 首屏必须可见「导出 JSON 备份」和「导入恢复」按钮；导入不限条数；清空数据二次确认；数据满 30 条温和提示备份。
7. 记账财务类：支出红、收入绿；货币符号 ¥；日期格式 YYYY-MM-DD 或 M月D日。
8. 函数调用链必须是单向 DAG：数据层 → 计算层 → 渲染层；渲染函数之间禁止互调；联动一律由事件处理函数改数据后调统一入口 `refreshAll()`。
9. localStorage key 统一前缀 `wb_{工作台id}_`；所有 JSON.parse 包 try-catch；字段变更向后兼容（读旧数据时给默认值，不丢已有数据）。
10. 每次交付前默读代码过一遍冒烟清单（见 references/quality-checklist.md）。
11. 浏览器兼容一律遵守 `references/compat-rules.md`：禁止 `new Date('YYYY-MM-DD')`、`:has()`、无降级的 `aspect-ratio`/`100vh` 等跨端陷阱写法；带降级属性必须双写旧值在前；目标是 iOS Safari 14+ 与主流安卓 WebView 一次跑通。

## 资产索引

- `assets/base-shell.html` — 工程骨架：设计令牌、响应式布局、顶栏、今日区、模块槽、Store 存储层（前缀隔离/导出导入/备份提醒）、refreshAll 架构、示例数据种子。

- `references/scenarios.md` — 12 类场景 × 推荐模块矩阵。
- `references/scenario-matching.md` — 场景匹配与兜底链规范：① 关键词精确 → ② 场景大类兜底 → ③ 默认通用模板 + 场景类型×最优色板表。生成前必查。
- `references/template-catalog.md` — 模板目录：`examples/` 已沉淀成品模板的登记表（场景、布局形态、色板 token、hero、氛围元素、兼容状态、可迁移视觉资产），作为审美基准资产索引。

- `references/quality-checklist.md` — 冒烟自检清单 + 代码质量标准。

## 按需加档（对标 workspace-builder 专家的差异化能力，用户提出时才实现）

以下能力在基础骨架中**不预置**（保持轻量），用户要求时现场实现，实现标准如下：

1. **家长/孩子双模式**：同页两个 Tab；家长模式需 4 位数字密码（首次设置存 localStorage，仅防误触不宣称加密）；家长可发布任务/设置奖励/确认兑换，孩子只能看任务/打卡/兑换。
2. **儿童向规格**：按钮 ≥50px、正文字号放大、配色鲜艳活泼（翻卡组件加 `fc-kid` 类即生效，其余模块照此模式扩展）。
3. **图片存储**：上传压缩到 800px 宽、最多 9 张、Canvas 转 base64 存 localStorage。
4. **记账 CSV 导出**：在 JSON 导出之外追加 CSV（BOM 头 `\uFEFF` 防乱码），字段：日期/类型/分类/金额/备注。
5. **底部 Tab 导航**：模块 ≥4 个或用户要求"像 App"时，移动端加底部 Tab（≥44px 高、适配安全区），PC 端保持单列堆叠。
6. **在线托管与多端同步**：本 skill 默认纯本地；用户要在线部署时改走资料库/sites 方案，不在本 skill 范围内。

## 迭代沉淀规则

每完成一个新工作台，若产出了可复用的新模块（如新的图表、新的卡片形态），把它的通用化版本（去掉业务字段、暴露 data-* 配置）按组件文件格式沉淀到 `assets/components/`，并同步登记到 `references/component-catalog.md`。组件库只增不删，保持向后可用。

**模板沉淀（新增）**：产出了一套视觉显著不同于已有 4 套（T1-T4）的高质量成品时，把它作为新参考模板存进 `examples/`，并登记到 `references/template-catalog.md`（含色板 token、布局、hero、可迁移视觉资产）。目标 12 套左右覆盖大多数场景；登记后自动进入第 0 步场景匹配的关键词库。
